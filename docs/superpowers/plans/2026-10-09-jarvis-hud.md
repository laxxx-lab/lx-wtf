# JARVIS HUD, Bildschirmblick und Einsatzmodi

Autorisierter Umfang: User hat HUD, Bildschirmblick/Markierungen und konfigurierbare Einsatzmodi in dieser Reihenfolge bestätigt. Erweiterung der bestehenden lokalen Electron-App, bestehende Hermes-Session/Windows-MCP behalten. Frontend-Design und Writing-Plans angewendet.

1. HUD: lokale reine Zustandsmaschine (task, genuine tool start/end, complete/error/interrupted, relevant alert), kompakte Glass/HUD-Karte links vom Orb ohne Fokusnahme; beendet nach6Sekunden, echte Ergebnisse statt Prozentfortschritt. Separate HTML/CSS/JS/Preload, kein Zugriff auf Tokens. Einstellungen HUD an/aus, Kamera/Mikrofon bleiben unabhängig. Tests Taskwechsel, veraltete Endereignisse, Fehler/Unterbrechung nicht als Erfolg.
2. Bildschirmblick: nur auf Wunsch, lokale ausgewählte Fenster-/Bildschirmquelle, Quelle+Zeitangabe, ein kurzlebiger Capture ohne Speichern. Lokales vorhandenes Qwen-VL für Textbeobachtung, nur Text zum Hermes-VPS. Keine Kamera-Verwechslung. Screen aktivieren/Quellenauswahl in Einstellungen. Eindeutige Bildschirmfragen gehen vor Kamerafragen. Tests ausgeschaltet/Quelleweg/Captureabbruch/keineBildweiterleitung. Agent erhält skill/API über bestehende Windows-MCP-Shell.
3. Markierungen: lokale transparente durchklickbare zeitlichbegrenzte Rahmen, Desktopkoordinaten mit DPI-Konvertierung und Monitorgrenzen. Aktuelle UIA-Positionen aus bestehendem Windows-MCP nutzen; keinen markierten Bereich automatisch anklicken. API nur validierte Rechtecke/Kurzlabel, klare Quelle,8Sekunden TTL; vor erneuter Positionierung aktuelle Snapshot nötig. Tests ungültige Rechtecke/Ausdehnung/DPI.
4. Modi: Gaming/Arbeit/Feierabend konfigurierbar; vom Nutzer ausgewählte lokale App-Verknüpfungen plus knapper Ablaufauftrag an Hermes; Hinweisprofil ruhig/normal, Kamera behalten/aus, optional Standby. Keine vorgegebenen Löschungen oder beliebigen Shellskripte. Leere Profile keine erfundenen Apps. Anzeigen was umgesetzt/was Hermes noch ausführen muss. Tests Eingabevalidierung, Appstartfehler, kein stilles Erfolgsmelden.
5. Integration: main IPC/preload/renderer, authenticated loopback API erweitern, control.ps1, Gateway-Skill aktualisieren/readback. HUD benutzt vorhandene Gatewayevents; neue Features werden vor Kameraintents verarbeitet. Keine tatsächlichen Hermes-Chat-Testaufträge ohne Nutzeranweisung.
6. Validierung: relevante Red/Green-Tests, gesamte bestehende Tests, native Smoke mit Kamera+Bildschirmaus; Bildschirm/Highlight nur mit eigener Testfensterquelle prüfen. Visuelle HUD-Prüfung/Screenshot. Normale App idle neu starten; bestehende Session/Autostart/Audioeinstellungen erhalten. Keine neuen bezahlten Dienste.

Ausführung im bestehenden persönlichen Git-Branch codex/hermes-windows. Erweiterung von drei unabhängigen UI/Logik-Bausteinen, Integration sequenziell. Ledger .superpowers/sdd/2026-10-09-jarvis/progress.md.
